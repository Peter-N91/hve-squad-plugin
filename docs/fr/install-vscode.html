Guide d’installation

Notes pour VS Code

Pour VS Code, il n’y a pas de différence notable par rapport à l’installation via le panneau Plugins de l’application de bureau — cette page est donc volontairement courte. Le seul point à connaître est l’alternative sans plugin, reposant uniquement sur MCP, présentée ci-dessous.

L’installation du plugin est identique à celle dans l’application de bureau

Le panneau Paramètres → Extensions → Copilot → Plugins de VS Code installe ce plugin de la même façon que l’application de bureau autonome Copilot, en utilisant le même manifeste .github/plugin/plugin.json. Consultez Installation : application de bureau pour la procédure détaillée — elle s’applique à VS Code sans modification, y compris l’obligation d’installer les deux plugins, hve-squad et hve-squad-hve-core, et de les mettre à jour ensemble. Deux règles restent inchangées : actualisez hve-squad-hve-core en le supprimant puis en le réinstallant, plutôt qu’en utilisant l’action de mise à jour, et n’installez pas le plugin officiel hve-core à ses côtés.

Alternative : MCP uniquement, sans installation de plugin

Si vous ne souhaitez pas du tout installer le plugin — par exemple, si vous voulez seulement accéder à la squad par des appels d’outils plutôt que par l’invocation directe d’agents — vous pouvez enregistrer directement le serveur compagnon @hve-squad/mcp dans le fichier .vscode/mcp.json d’un espace de travail. C’est la configuration décrite dans le fichier skills/squad/mcp-server.template.json de ce plugin : 

{
  "servers": {
    "hve-squad": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@hve-squad/mcp@0.7.1"]
    }
  }
}

Épinglez une version précise plutôt que d’utiliser simplement @hve-squad/mcp : sans version épinglée, npx sélectionne la version marquée latest au moment de l’exécution ; deux machines configurées à des dates différentes obtiennent donc des serveurs différents. Chaque version publiée de @hve-squad/mcp est construite pour une version précise de hve-squad, selon la même discipline d’appariement que les deux entrées de la marketplace.

Fusionnez cette entrée dans .vscode/mcp.json (ne remplacez pas les serveurs dont vous dépendez déjà), rechargez VS Code, et les outils de la squad (squad_research, squad_plan, squad_review, squad_architect, squad_run) deviennent invocables par le modèle — sans installer les agents ni les skills du plugin. Consultez Architecture pour comprendre le lien entre cette interface d’appels d’outils et l’interface d’invocation directe des agents du plugin.

Pourquoi proposer cette voie séparément. La voie MCP uniquement s’adresse aux hôtes ou aux workflows qui consomment des outils mais ne disposent d’aucune interface d’installation de plugins (ou à un utilisateur qui souhaite invoquer des outils sans adopter l’espace de noms du plugin). La plupart des utilisateurs de VS Code qui procèdent à une installation interactive devraient simplement utiliser le panneau de paramètres Plugins.
