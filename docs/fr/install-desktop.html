Guide d’installation

Installation via l’application de bureau / les paramètres Plugins de VS Code

L’application de bureau GitHub Copilot et les paramètres des plugins Copilot de VS Code permettent tous deux l’installation à partir de la même entrée de la marketplace — aucun terminal n’est nécessaire.

Prérequis

  • L’application de bureau GitHub Copilot, ou VS Code avec l’extension GitHub Copilot, avec une session connectée
  • Un accès en lecture à Peter-N91/hve-squad-plugin (dépôt public — aucune autorisation d’accès supplémentaire requise)

1. Ouvrir le panneau de paramètres Plugins

Dans VS Code : ouvrez Paramètres → Extensions → Copilot → Plugins (ou le panneau Plugins équivalent dans l’application de bureau autonome). Ce panneau répertorie les plugins installés et propose une action de recherche et d’installation pour en ajouter.

2. Rechercher et installer les deux plugins

Recherchez Peter-N91/hve-squad-plugin (ou collez l’URL du dépôt si le panneau le permet). Cette marketplace publie deux entrées, et vous avez besoin des deux :

  • hve-squad — les agents, skills et hooks propres à la squad, ainsi que son entrée de serveur MCP
  • hve-squad-hve-core — les agents et skills de microsoft/hve-core auxquels les rôles de la squad délèguent le travail, avec une version épinglée au commit exact sur lequel la version correspondante de hve-squad a été validée

Choisissez Installer pour chacun. Le client récupère .github/plugin/plugin.json depuis ce dépôt, de la même manière que le CLI, et enregistre les mêmes agents, skills, hooks et entrée de serveur MCP.

Installez hve-core depuis cette marketplace, et non depuis sa propre source. La plupart des rôles de la squad correspondent à un agent hve-core ; avec hve-squad seul, ces rôles restent donc impossibles à résoudre. Installer hve-core directement depuis microsoft/hve-core fournit au contraire la version qui y est actuellement disponible, laquelle peut être en avance sur les tables de routage et les chartes de rôle auxquelles votre version installée de la squad fait référence. L’entrée hve-squad-hve-core épingle le commit validé : c’est précisément la raison de sa publication ici.

3. Vérifier le fonctionnement dans la conversation

Ouvrez Copilot Chat et demandez-lui d’utiliser la squad — par exemple, "use the squad to research this codebase" — ou adressez-vous directement à un agent par son nom qualifié par l’espace de noms, hve-squad:squad-coordinator. Une invocation réussie affiche la réponse du coordinateur de la squad dans la vue de conversation.

Mises à jour ultérieures

Cette marketplace ne définit pas autoUpdate : les mises à jour sont donc explicites. Lorsqu’une nouvelle version paraît, mettez à jour les deux entrées au cours de la même session — chaque version de hve-squad épingle le commit hve-core sur lequel elle a été validée ; faire évoluer l’une sans l’autre réintroduit donc précisément le décalage de versions que cet épinglage vise à éviter.

Dans le panneau Plugins, actualisez la liste de la marketplace, puis choisissez l’action de mise à jour pour hve-squad. Pour hve-squad-hve-core, supprimez-le puis réinstallez-le plutôt que d’utiliser l’action de mise à jour.

hve-squad-hve-core doit être supprimé puis réinstallé, et non mis à jour. Sa version enregistrée provient du fichier plugin.json de hve-core en amont, et non de l’entrée de cette marketplace : une version qui ne change que le commit épinglé laisse donc ce numéro inchangé. Toute action de mise à jour — bouton du panneau ou copilot plugin update — le signale alors comme déjà à jour et conserve les anciens fichiers. Le supprimer efface cet état, ce qui permet à la réinstallation de récupérer le nouveau commit épinglé. Consultez Installation : Copilot CLI pour l’explication complète et les commandes exactes.

N’installez pas également le plugin officiel hve-core. Si vous utilisez la squad, obtenez hve-core uniquement via l’entrée hve-squad-hve-core de cette marketplace. Installer le plugin officiel hve-core à ses côtés enregistre une seconde copie de chaque agent et skill hve-core, qui suit la version courante en amont plutôt que le commit validé. Les rôles de la squad sont associés aux agents hve-core par leur nom : une délégation peut donc aboutir à cette copie non épinglée et contourner silencieusement l’épinglage. Le nom distinct de l’entrée permet d’éviter un conflit à l’installation ; il ne constitue pas une recommandation d’utiliser les deux.

Même manifeste, même résultat. L’installation via le panneau Plugins de l’application de bureau ou de VS Code et la commande CLI copilot plugin install utilisent toutes deux le même manifeste .github/plugin/plugin.json dans ce dépôt — il n’existe aucune distribution distincte réservée à l’application de bureau qu’il faudrait synchroniser. Consultez Installation : Copilot CLI pour les étapes équivalentes en ligne de commande et le diagramme du déroulement de l’installation.
