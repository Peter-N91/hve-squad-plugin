Guide d’administration

Guide opératoire de déploiement à l’échelle de l’entreprise : imposer l’installation de hve-squad dans toute l’organisation

Pour les administrateurs GitHub Copilot d’entreprise qui souhaitent que chaque développeur de leur entreprise reçoive automatiquement le plugin hve-squad, sans devoir exécuter lui-même copilot plugin install.

Cette page est une copie du guide opératoire, légèrement remise en forme pour sa lecture sur le site Pages. La source Markdown fait autorité pour toute personne qui la consulte directement sur GitHub : docs/enterprise-push-runbook.md.

Fonctionnement

Un administrateur d’entreprise ajoute une entrée sous enabledPlugins dans le fichier copilot/managed-settings.json de l’entreprise (géré côté serveur, dans un dépôt .github-private — la méthode de déploiement par défaut et recommandée), ou dans un fichier managed-settings.json distribué par MDM ou par fichier, pour une application limitée au client local. enabledPlugins et extraKnownMarketplaces se complètent : le dépôt de ce plugin ne fait pas partie des places de marché intégrées par défaut à Copilot ; les paramètres de l’entreprise doivent donc également l’enregistrer via extraKnownMarketplaces avant de le référencer dans enabledPlugins. Une fois la modification enregistrée par commit et poussée sur la branche par défaut du dépôt de gouvernance, chaque client pris en charge (Copilot CLI, VS Code, JetBrains, l’application GitHub Copilot, l’agent cloud Copilot) récupère la stratégie à la prochaine connexion ou sous environ une heure, et installe automatiquement le plugin pour chaque utilisateur — celui-ci a seulement besoin d’un accès en lecture à Peter-N91/hve-squad-plugin (public, sous licence MIT) ; aucune licence ni autorisation d’accès supplémentaire n’est donc requise.

Exemple d’entrée dans managed-settings.json

{
  "extraKnownMarketplaces": {
    "hve-squad-plugin": {
      "source": {
        "source": "github",
        "repo": "Peter-N91/hve-squad-plugin",
        "ref": "main"
      }
    }
  },
  "enabledPlugins": {
    "hve-squad@hve-squad-plugin": true
  }
}

La clé de enabledPlugins est PLUGIN-NAME@MARKETPLACE-NAME — hve-squad est le nom du plugin défini dans le fichier .github/plugin/plugin.json de ce dépôt, et hve-squad-plugin est le nom de la place de marché défini dans .github/plugin/marketplace.json, dans son champ name de premier niveau. Les deux doivent correspondre exactement, sans quoi la référence n’aboutit à rien.

Notes pour les administrateurs

  • Définir { "overridable": true } sur l’une ou l’autre de ces clés dans les paramètres par défaut de l’entreprise permet à chaque équipe de l’entreprise d’ajouter d’autres places de marché ou plugins à ce socle via copilot/team-mappings.json et des fichiers propres à chaque équipe dans copilot/teams/ — consultez le guide GitHub Configuration des paramètres gérés par l’entreprise pour connaître la syntaxe de remplacement des valeurs.
  • Un plugin ou une place de marché épinglé de cette manière ne peut pas être désactivé ni redirigé vers une autre source localement par un utilisateur — la valeur gérée prévaut toujours pour cette entrée, et le tableau de bord /plugins de la CLI lui attribue la mention Managed.
  • Ce guide opératoire décrit uniquement le mécanisme. L’ajout de cette entrée au fichier managed-settings.json d’une organisation donnée relève de cette organisation, et non d’une intervention de ce dépôt ou de ses responsables pour le compte d’une organisation qui l’adopte.
